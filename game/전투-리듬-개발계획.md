# 전투 리듬·생존 기능 구현 계획

> 실행 방식: 이 세션에서 직접 구현하고 각 단계에서 회귀 테스트를 실행한다.

**목표:** 차징 공격·대시·제한된 회복 포션을 추가하고 적과 보스의 압박을 읽고 대응할 수 있는 수준으로 높인다.

**구조:** 공용 전투 판정과 수치 규칙은 `combat.js`에 둔다. `index.html`은 입력·적 AI·보스 패턴·HUD를 연결하고, 기존 API와 MySQL 경로는 유지한다.

**기술:** 바닐라 JavaScript, HTML 스모크 테스트, Python unittest, Docker Compose.

**설계:** `game/전투-리듬-설계.md`

## 범위 제약

- 변경은 `game/` 안으로 한정한다. Unity 프로젝트와 기존 백엔드·DB 스키마는 수정하지 않는다.
- 플레이어는 매 진행마다 포션 2개를 받고, 각 포션은 최대 체력의 10%를 회복한다. 자연 회복·발전기 회복은 제거한다.
- 차징은 공격 키 0.65초 유지, 차징 중 이동 속도 60%, 대시는 5초 쿨타임으로 한다.
- 적 수를 늘리되 구역당 동시 적 상한을 두고, 공격 판정에는 회피 가능한 전조를 둔다.
- 중간 보스 2페이즈, 최종 보스 3페이즈를 유지하며 각 페이즈에 패턴 선택지를 추가한다.

## 주요 검토 항목

- 입력 반복·키를 놓지 않음: 한 번의 공격 입력만 처리하고 공격 중복 피해를 막는다.
- 회복 경계값: 포션 0개·최대 체력·사망 상태에서는 회복 불가 및 포션 미소모를 확인한다.
- 대시 상태 전환: 차징 취소·쿨타임·무적 지속 시간을 검증한다.
- 적 동시 공격: 증원 직후 공격이 겹치거나 적 상한을 넘지 않는지 확인한다.
- 보스 페이즈 전환: 체력 경계와 공격 전조·활성·회복을 확인한다.
