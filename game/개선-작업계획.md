# LAST SPARK 구현 현황

## 반영된 내용

- [x] 연구동을 3개 층으로 압축하고 층마다 발전기 한 대를 배치했다.
- [x] 방 입장부터 경비 유닛을 배치하고 순찰·감지·추적 동작을 연결했다.
- [x] 연구동 층 진입과 발전기 작동 때 천장 해치 경고 후 적을 투입한다.
- [x] 층별 포탑 조준·발사와 적의 근접·사격·돌진 유형을 추가했다.
- [x] 은폐 지점을 연구동 층마다 하나로 줄였다.
- [x] 근접 공격 판정에 전방 사거리·수직 겹침·적 크기를 반영하고 보스도 표적 위치를 공격한다.
- [x] 플레이어 원거리 공격 입력과 투사체를 제거했다.
- [x] 전체 화면 글리치를 제거하고 전선 주변 스파크와 조도 복구를 적용했다.
- [x] 운용 기록과 현장 메모로 도입 서사를 정리하고, 연구동 UI에 이끼·파손 장비·짧은 타격 피드백을 추가했다.
- [x] 익명 플레이 기록 API, MySQL 스키마, Nginx 정적 호스트와 Compose 실행 구성을 `game/`에 추가했다.
- [x] 기본 근접 공격에 회복 주기를 두고, 길게 눌렀다 놓는 차징 공격과 차징 이동 감속을 추가했다.
- [x] 전 페이즈에서 5초 재사용 대시와 출격당 2회 응급 패치(최대 체력 10%)를 제공한다. 자연·발전기 체력 회복은 제거했다.
- [x] 일반 구역 경비와 연구동 투하 병력을 늘리고 동시 적 수를 5기로 제한했다.
- [x] 기존 보스 페이즈 수를 유지하고 페이즈별 두 종류 패턴과 공격 후 반격 창을 추가했다.

## 확인 결과

- `python -m unittest discover -s game/server/tests -v`: API 검증 9개 통과.
- `python -m py_compile game/server/app.py game/server/tests/test_app.py`: 통과.
- `python game/tools/build_asset_manifest.py --check`: 스프라이트 시트 244개 확인.
- `docker compose -f game/docker-compose.yml --env-file game/.env.example config --quiet`: 통과.
- Docker Compose로 웹·API·MySQL을 빌드한 뒤 `/api/health`와 프로필 저장·재조회 왕복을 확인했다. MySQL 8.4에서 upsert 컬럼이 모호했던 오류도 수정했다. 검증용 프로필은 삭제했고 컨테이너는 중지했다.
- 전투 규칙과 게임플레이 런타임 테스트는 `tests/combat-rules.test.cjs`, `tests/gameplay-runtime.test.cjs`로 실행한다. 브라우저 전용 스모크 페이지도 요구 변경에 맞춰 갱신했다.
